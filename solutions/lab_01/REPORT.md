## Задание 1. От исходного кода к байткоду

### Часть 1. Режимы запуска

Попробовал запустить `2 + 3 * 4` в REPL — результат сразу вывелся (14). Потом записал то же самое в файл и запустил — ничего не вывелось.

Разница в том, что REPL автоматически печатает результат каждого выражения, а при запуске файла Python просто вычисляет выражение и выбрасывает результат. Чтобы что-то вывелось — нужен явный `print()`.

В `task_1.py` сделал вывод через `print(2 + 3 * 4)`.

### Часть 2. Выражения и инструкции

Код:
```python
print(2 + 3 * 4)
course = "Python"
hours = 4 * 2
print(f"{course}: {hours} часов")
```

- **Инструкции** (целые строки): все 4 строки — либо присваивание, либо вызов функции.
- **Выражения** (то, что имеет значение): `2 + 3 * 4`, `4 * 2`, `"Python"`, `course`, `hours`, `f"{course}: {hours} часов"`.
- **Литералы**: `2`, `3`, `4`, `"Python"`.
- **Созданные имена**: `course`, `hours`.

### Часть 3. AST и байткод

Версия: **Python 3.14.7**

Фрагмент AST (`python -m ast task_1.py`):
```
Assign(
   targets=[Name(id='course', ctx=Store())],
   value=Constant(value='Python'))
```
— это присваивание `course = "Python"`.

```
BinOp(left=Constant(value=4), op=Mult(), right=Constant(value=2))
```
— арифметика `4 * 2`.

```
Call(func=Name(id='print', ctx=Load()), args=[...])
```
— вызов `print()`.

Фрагмент байткода (`python -m dis task_1.py`):
```
2     LOAD_CONST   1 ('Python')
      STORE_NAME   1 (course)

3     LOAD_SMALL_INT  8
      STORE_NAME   2 (hours)

4     LOAD_NAME    0 (print)
      PUSH_NULL
      ...
      CALL         1
      POP_TOP
```

`LOAD_CONST` / `LOAD_SMALL_INT` — загружают константу на стек. `CALL` — вызывает функцию. Интересно, что `4 * 2` компилятор сразу посчитал и положил готовое `8` — это константная свёртка.

### Контрольный вопрос

**Почему байткод CPython не является машинным кодом?**

Байткод выполняется виртуальной машиной CPython, а не процессором напрямую. Машинный код — это инструкции конкретной архитектуры (x86, ARM), которые процессор выполняет аппаратно. Байткод Python платформонезависим.

## Задание 2. Имена, объекты и сравнение

Код в `task_2.py`:
```python
a = 1000
b = a
c = int("1000")
```

### Прогноз (до запуска)
```python
# a == b → True (значения совпадают)
# a is b → True (b = a, одна и та же ссылка)
# a == c → True (значения совпадают)
# a is c → True (думал что тоже интернирует)
```

### Фактический результат
```
Типы: <class 'int'> <class 'int'> <class 'int'>
Идентификаторы: 2119786738128 2119786738128 2119790140496
a == b: True
a is b: True
a == c: True
a is c: False   <- ошибся с прогнозом
```

`a is c` оказался `False` — `int("1000")` создал новый объект в памяти, несмотря на то что значение то же. Число 1000 не попадает в диапазон кэшируемых CPython значений (-5..256), поэтому каждый раз создаётся новый объект.

### Схема имён и объектов

```
a ─────┐
       ▼
b ──► [int: 1000, id=...8128]

c ──► [int: 1000, id=...0496]   (другой объект!)
```

После `c = None`:
```
a ─────┐
       ▼
b ──► [int: 1000, id=...8128]

c ──► [None]
```

Проверка что `c` это `None`:
```python
c = None
print(c is None)  # True
```

### Строки и интернирование
```python
first = "python"
second = "py" + "thon"
print(first == second)  # True
print(first is second)  # True
```
Оба `True` — компилятор свернул `"py" + "thon"` в `"python"` и проинтернировал, поэтому объект тот же. Это деталь реализации CPython, полагаться на неё нельзя.

### Правило: `==` vs `is`

- `is` — только для `None`, `True`, `False` (синглтоны).
- `==` — для всего остального (числа, строки, объекты).

### Контрольные вопросы

1. **`b = a` создаёт копию?** — Нет. Просто ещё одна ссылка на тот же объект.
2. **Что возвращают `type()` и `id()`?** — `type()` — класс объекта, `id()` — его адрес в памяти (в CPython).
3. **Почему `None` проверяют через `is`?** — Потому что `None` синглтон, его экземпляр всегда один. `is` дешевле и семантически точнее.

## Задание 3. Числовые типы, операции и преобразования

### Эксперимент A. int-арифметика (x=17, y=5)

```
x + y  = 22   <class 'int'>
x - y  = 12   <class 'int'>
x * y  = 85   <class 'int'>
x / y  = 3.4  <class 'float'>
x // y = 3    <class 'int'>
x % y  = 2    <class 'int'>
x ** y = 1419857  <class 'int'>
```

`/` всегда возвращает `float` даже если делится нацело. `//` — целочисленное деление, результат `int` (округление вниз).

### Эксперимент B. Большие числа

```python
2 ** 1000 = 107150860718626732...  (303 цифры, тип int)
```

В Python `int` не ограничен разрядностью — он хранит числа произвольного размера. В C/Java при переполнении число "обрезается", здесь — нет.

### Эксперимент C. float и погрешность

```
result = 0.1 + 0.2  →  0.30000000000000004
result == 0.3       →  False
result - 0.3        →  5.551115123125783e-17
math.isclose(result, 0.3)  →  True
```

0.1 и 0.2 в двоичной системе — бесконечные дроби, при хранении округляются. Сумма накапливает ошибку. Поэтому `float` нельзя сравнивать через `==`, только через `math.isclose()`.

### Эксперимент D. Преобразования типов

```
int("42")     → 42    <class 'int'>
float("3.14") → 3.14  <class 'float'>
str(2026)     → '2026' <class 'str'>
bool(0)       → False  <class 'bool'>
bool(-1)      → True   <class 'bool'>
bool("")      → False  <class 'bool'>
bool("False") → True   <class 'bool'>   <- неожиданно
complex(2,-3) → (2-3j) <class 'complex'>
Действительная часть: 2.0
Мнимая часть: -3.0
```

`bool("False")` = `True` потому что строка непустая. `bool()` смотрит на длину строки, а не на её содержимое.

**Falsy-значения из эксперимента:** `0` и `""`.

### Контрольные вопросы

1. **Почему `int / int` → `float`?** — По дизайну Python 3: деление математически всегда может дать дробь, поэтому всегда `float`.
2. **`int("42")` vs `int(42.9)`?** — Первое парсит строку (требует только цифры), второе усекает дробную часть (даёт 42).
3. **Falsy в эксперименте D?** — `bool(0)` и `bool("")`.

## Задание 4. Строки, Unicode и форматирование

### Результаты

```python
student = "Анна Смирнова"
```

```
student[0]    → 'А'
student[-1]   → 'а'
student[:4]   → 'Анна'
student[5:]   → 'Смирнова'
student.upper() → 'АННА СМИРНОВА'
student.lower() → 'анна смирнова'
initials      → 'А.С.'
course[::-1]  → 'nohtyP ан яинавориммарgorп ывонсО'
```

Три способа форматирования — вывод одинаковый:
```
Анна Смирнова — Основы программирования на Python: 7/10 (70.0%)
```

### Unicode

```python
symbol = "Я"
ord("Я")        → 1071
chr(1071)       → 'Я'
"Я".encode("utf-8") → b'\xd0\xaf'
len("Я")        → 1   (один символ)
len(b'\xd0\xaf') → 2  (два байта в UTF-8)
```

Кириллица в UTF-8 занимает 2 байта, поэтому длина строки и длина байт различаются.

### Неизменяемость строк

```python
# student[0] = "О"  → TypeError: 'str' object does not support item assignment
```

Строку нельзя изменить по индексу — это неизменяемый тип. Методы вроде `.upper()` создают новую строку, а не меняют старую.

### Контрольные вопросы

1. **Почему `len(symbol)` ≠ `len(symbol.encode("utf-8"))`?** — `len(str)` считает символы (code points), `len(bytes)` — байты. UTF-8 кодирует кириллицу двумя байтами.
2. **`text[start:stop:step]`** — `start` включается, `stop` не включается, `step` — шаг (отрицательный = реверс).
3. **Почему строка «неизменяемая» если `.upper()` что-то меняет?** — `.upper()` возвращает новый объект. Исходная строка не трогается.
