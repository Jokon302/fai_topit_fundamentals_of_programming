## Задание 1. Имена, ссылки и изменяемость

### Эксперимент A. Неизменяемый объект (int)

Код из `task_1.py`:
```python
a = 10
b = a
a += 1
```

#### Прогноз (до запуска)
```python
# a == b → True (оба смотрят на 10)
# a is b → True (один и тот же объект)
# После a += 1: a станет 11, b останется 10, id(a) поменяется
```

#### Фактический результат
```text
До a += 1:
10 10
140730861839920 140730861839920
После a += 1:
11 10
140730861839952 140730861839920
```

Значение `b` не изменилось, потому что `int` — неизменяемый тип. Операция `a += 1` не меняет само число 10 в памяти, а создаёт новый объект 11 и привязывает имя `a` к нему. Имя `b` при этом продолжает указывать на старое число 10.

### Эксперимент B. Изменяемый объект (list)

```python
first = [10, 20]
second = first
second.append(30)
```

#### Прогноз
```python
# second = first — копии нет, просто вторая ссылка на тот же список
# second.append(30) поменяет список на месте, first тоже станет [10, 20, 30]
```

#### Фактический результат
```text
До append:
[10, 20] [10, 20]
После second.append(30):
[10, 20, 30] [10, 20, 30]
```

Оба списка изменились, потому что `first` и `second` ссылались на один физический объект в памяти (`id` совпадают).

Дальше в `task_1.py` переназначил `second = [10, 20, 30]`:
```python
print(first == second)  # True (элементы одинаковые)
print(first is second)  # False (разные списки в памяти)
second.append(40)
# first остался [10, 20, 30], а second стал [10, 20, 30, 40]
```

#### Схемы связей имён и объектов

До переназначения:
```text
first ───┐
         ▼
second ──► [list: [10, 20, 30]]
```

После `second = [10, 20, 30]` и `second.append(40)`:
```text
first  ──► [list: [10, 20, 30]]
second ──► [list: [10, 20, 30, 40]]
```

- Вывел состояние до и после изменений, проверил через `is not` идентичность объектов в памяти и подтвердил полную независимость через `assert`.

### Контрольные вопросы

1. **`second = first` меняет сам объект?** — Нет, просто создаёт ещё одно имя для того же объекта.

## Задание 2. Поверхностное и глубокое копирование

В `task_2.py` создал структуру курсов и сделал три варианта копирования:
```python
original = [["Python", 5], ["Algorithms", 4]]
alias = original
shallow = original.copy()
deep = copy.deepcopy(original)
```

1. Сделал `original.append(["Databases", 5])`:
   - `alias` изменился (это тот же список).
   - `shallow` и `deep` не изменились — внешние списки у них свои.
2. Сделал `original[0][1] = 3` (поменял оценку):
   - `alias` изменился.
   - `shallow` **тоже изменился** на оценку 3! Потому что `.copy()` скопировал только внешний список, а ссылки на вложенные списки остались общими (`shallow[0] is original[0] == True`).
   - `deep` остался со старой оценкой 5, потому что `deepcopy()` продублировал и все вложенные списки тоже.

---

### Таблица наблюдений

| Способ | Новый внешний список | Новые вложенные списки | Изменения независимы |
|---|---|---|---|
| `alias = orig` | Нет | Нет | Нет (меняется всё) |
| `orig.copy()` | Да | Нет | Частично (вложенные общие) |
| `copy.deepcopy(orig)` | Да | Да | Да (полная копия) |

---

### Ошибка с матрицей: `[[0] * 3] * 3`

Попробовал сделать матрицу через умножение:
```python
wrong_matrix = [[0] * 3] * 3
wrong_matrix[0][0] = 1
# Получилось: [[1, 0, 0], [1, 0, 0], [1, 0, 0]]
```
Единица вылезла во всех трех строках, потому что `* 3` просто трижды скопировал ссылку на один и тот же список `[0, 0, 0]`. Все три строки матрицы — это один объект (`id` совпадают).

Как правильно: через списковое включение:
```python
correct_matrix = [[0] * 3 for _ in range(3)]
correct_matrix[0][0] = 1
# Получилось: [[1, 0, 0], [0, 0, 0], [0, 0, 0]]
```
Тут на каждом шаге цикла `[0] * 3` создаёт отдельный список в памяти.

---

### Контрольные вопросы

1. **Чем поверхностная копия отличается от глубокой?** — Поверхностная копирует только внешний контейнер, а элементы внутри оставляет по ссылкам. Глубокая рекурсивно копирует всё, включая вложенные структуры.
2. **Почему не использовать `deepcopy` везде?** — Оно медленное, жрёт больше памяти, плюс некоторые системные вещи (файлы, сокеты) скопировать вообще нельзя.
3. **Когда хватает поверхностной копии?** — Когда список одноуровневый или внутри лежат только неизменяемые типы (числа, строки).

## Задание 3. Подсчет ссылок и время жизни объекта

### Часть 1. Счетчик ссылок (`sys.getrefcount`)

Результаты из `task_3.py`:
```text
После создания: 2
После alias: 3
После помещения в контейнер: 4
После del alias: 3
После очистки контейнера: 2
```

- `sys.getrefcount(data)` показывает на 1 больше, потому что сам вызов функции создаёт временную ссылку на объект при передаче аргумента.
- **Увеличивают счётчик:** присваивание переменной, передача в функцию, добавление в список/словарь.
- **Уменьшают счётчик:** `del`, перезапись переменной, удаление из списка, выход из функции.
- `del alias` не удаляет сам объект — он просто убирает имя `alias` и делает счётчику `-1`. Объект удаляется только тогда, когда счётчик падает до нуля.

### Часть 2. Слабые ссылки (`weakref`)

```python
record = Record()
weak_record = weakref.ref(record)
print(weak_record())  # <Record object>
del record
print(weak_record())  # None
```

Слабая ссылка не увеличивает счётчик ссылок. Как только удалили обычную переменную `record`, объект сразу стёрся из памяти, а слабая ссылка вернула `None`.
Это полезно для кэшей: чтобы кэш хранил ссылки, но не мешал сборщику удалять ненужные данные.

### Часть 3. Слабый словарь `WeakValueDictionary`

Зарегистрировал три объекта. На два оставил обычные ссылки, а на `temp` удалил (`del temp`). В итоге ключ `'temp'` сам мгновенно пропал из словаря:
```text
Реестр в начале: ['first', 'second', 'temp']
После del temp:  ['first', 'second']
```
Словарь сам чистит записи, когда на объекты больше нет сильных ссылок.

---

### Контрольные вопросы

1. **Когда объект удаляется подсчётом ссылок?** — Когда счётчик ссылок становится равен 0.
2. **Память сразу отдаётся Windows?** — Не всегда. CPython держит память в своих пулах для новых объектов и отдаёт её системе только целыми большими блоками (аренами).
3. **Чем сильная ссылка отличается от слабой?** — Сильная держит объект в памяти (счётчик +1), а слабая просто наблюдает за ним и удалению не мешает.

### Контрольные вопросы

## Задание 5. Исследование потребления памяти

### Часть 1. Размеры объектов (`sys.getsizeof`)

```text
Пустой список []:       56 байт
Список из 10 чисел:     136 байт
Кортеж из 10 чисел:     128 байт
Строка из 10 символов:  51 байт
Число 42:               28 байт
Объект None:            16 байт
```

`sys.getsizeof()` показывает только размер самой структуры списка (заголовок + массив указателей по 8 байт). Сами числа лежат в других ячейках памяти, их вес сюда не входит.

---

### Часть 2. Рост списка при `append`

```text
Старт: длина 0, размер 56 байт
Шаг 1:  размер 88 байт  (+32)
Шаг 5:  размер 120 байт (+32)
Шаг 9:  размер 184 байт (+64)
Шаг 17: размер 248 байт (+64)
Шаг 25: размер 312 байт (+64)
...
Шаг 93: размер 920 байт (+128)
```

- Список увеличивает размер **не на каждом append**, а скачками.
- Это сделано с запасом: перевыделять память на каждый элемент было бы слишком медленно. Запас даёт быструю амортизированную вставку $O(1)$.
- Длина — сколько элементов лежит сейчас, а размер памяти — сколько мест под указатели выделено заранее.

---

### Часть 3. Измерение через `tracemalloc`

Сравнение `list(range(100_000))` и `range(100_000)`:

| Сценарий | Элементов | getsizeof | Пиковая память (tracemalloc) |
|---|---|---|---|
| `list(range(100_000))` | 100 000 | 800 056 байт | ~3874 KB (~3.9 МБ) |
| `range(100_000)` | 100 000 | 48 байт | 0.00 KB |

- `list` реально создаёт в памяти 100 000 ячеек под указатели и жрёт почти 4 МБ.
- `range` ничего не хранит в памяти: это просто объект из трёх чисел (`start`, `stop`, `step`), который весит всего 48 байт и выдаёт числа на лету в цикле.

### Практическая задача (`memory_report.py`)

Собрал итоговую утилиту `memory_report.py`: она сначала сохраняет результаты всех измерений (`count`, `size`, `cur_kb`, `peak_kb`) в структуре данных (список словарей), а затем отдельной функцией форматирует и печатает сводный отчёт и отношение пикового потребления памяти.

---

### Три способа экономить память:
1. **Использовать генераторы и `range` вместо списков** — незачем материализовать миллион чисел, если по ним нужно просто пройтись циклом.
2. **Использовать кортежи (`tuple`) вместо списков для констант** — кортеж неизменяем и не держит лишнюю память про запас под `append`.
3. **Использовать слабые ссылки `weakref` для кэшей** — чтобы забытые объекты не висели в памяти вечно.
